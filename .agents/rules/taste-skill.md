# Taste-Skill (v2.5 / v2.1+) — التوجيه الفني، فحص المتصفح الحقيقي، ولوحات التحكم الصادقة

> هذه القاعدة تدمج وتفعّل مهارة **Taste-Skill** (من تطوير Leon) داخل مشروع `Forex Trading System` وبيئة ومحرر Antigravity.
> **القاعدة الحاكمة الصارمة:** تتكامل هذه المهارة مع قاعدة `AGENTS.md` الأولى: «كل رقم في هذا المستودع يجب أن يكون مقيساً. لا تُضِف وعداً ولا رقماً مُلفَّقاً».

---

## 1. الفلسفة الأساسية ونطاق العمل (Core Philosophy & Scope)

تهدف مهارة `Taste-Skill` (تُعرف أيضاً بـ `design-taste-frontend`) إلى إيقاف «عشوائية الذكاء الاصطناعي» (AI Slop) في الواجهات الأمامية وصفحات الويب. تُلزم الوكيل بالتخلي عن التصاميم المعلبة، والتدرجات البنفسجية الزائفة، والمربعات العائمة عديمة المعنى، وتفرض بدلاً منها:
- **لغة بصرية ومادية صادقة (Material & Honest Identity):** واجهات احترافية ومصقولة بمستوى منتجات عالمية رائدة (مثل Linear، Figma، وx.ai).
- **لوحات تحكم مالية هادئة وصادقة (Calm & Honest Dashboards):** منذ إصدار 2.1+، تدعم المهارة بناء شاشات البيانات والرسوم البيانية المخصصة للأنظمة المالية والتقنية دون أي تزييف أو تشويه بصري.
- **التصحيح البصري الذاتي عبر متصفح Chrome الحقيقي (Autonomous Visual Self-Correction):** فتح الصفحة تلقائياً في وضع Headless، والتقاط صور شاشة (Screenshots)، وفحص الأخطاء عبر بروتوكول فحص حتمي وتصحيحها قبل تسليم الكود.

## 2. القواعد المنزلية التسع الصارمة (The 9 House Rules)

هذه القواعد غير قابلة للتفاوض وتسبق أي قرار تصميمي آخر:

1. **منع التسميات التوضيحية أو الاعتذارية أسفل الصور (No Captions Under Visuals):** لا يُكتب سطر شرح أو تبرير تحت أي صورة أو رسم بياني أو مجسم ثلاثي الأبعاد. حقوق النشر توضع في سطر موحد في تذييل الصفحة فقط.
2. **كل عنصر بصري يُعرض بالكامل ولا تُترك خلفية فارغة (Every Visual Renders, Never Empty):** يجب أن يظهر كل عنصر بصري كامل المعالم عند المقاسات الأربعة: `1440px`، `1024px`، `768px`، و`390px`.
3. **قسم واحد فقط لكل شاشة (One Section Per Screen):** شاشة البطل (Hero) تملأ الشاشة الأولى كاملة دون تلصص من القسم التالي، وكل قسم تالٍ يمتد شاشة أو شاشتين بالضبط عند دقة `1440x900`.
4. **تطابق الهوامش اليمنى واليسرى (Equal Left & Right Content Edges):** محاذاة دقيقة وموحدة لكافة الكتل والحاويات دون أي شذوذ أو انزلاق أفقي.
5. **تفاعلات دقيقة وهادئة عند التمرير (Hover Micro-Animations):**
   - البطاقات التفاعلية ترتفع بمقدار `2px` بهدوء.
   - الصور تُكبّر بنسبة طفيفة `1.02` إلى `1.03` داخل إطارها المقصوص.
   - الأزرار تستجيب للحوم والضغط (`step & press`).
   - دورات حركة البطاقات تتكرر كل `2.5` إلى `4` ثوانٍ وتتوقف عند تمرير الفأرة.
   - **ممنوع تماماً:** تأثيرات الإمالة ثلاثية الأبعاد (3D tilt)، الكاروسيل العشوائي، والتبويبات ذات التوقيت الآلي القسري.
6. **صور فوتوغرافية حقيقية وواجهات فعلية (Real Photographs & True UI):** استخدام واجهات المنتج الحقيقية (`app-frame`)، ورندرات دقيقة للمنتجات التقنية، وتجنب الصور التعبيرية الساذجة.
7. **أيقونات منتجات حقيقية كاملة الألوان (Real Full-Colour Icons):** استخدام الأيقونات الأصلية للبرمجيات والأدوات المعروفة، ومخططات توضيحية دقيقة ومتحركة لنبضات تدفق البيانات.
8. **المؤثرات البرمجية والـ Shaders محصورة بالأنظمة التقنية فقط (Shader Effects Strictly for Tech):** خلفيات WebGL والـ Shaders مسموحة فقط للمنتجات البرمجية، والمالية (Fintech)، والذكاء الاصطناعي، وأدوات المطورين؛ ولا تُستخدم للمتاجر أو الأماكن التقليدية.
9. **نظافة ونزاهة العناوين والبيانات (Address & Data Hygiene):** استخدام شوارع ومناطق عامة واقعية دون اختلاق أرقام ضريبية أو سجلات تجارية زائفة، مع اعتماد النطاقات الآمنة `.example` للمراسلات الافتراضية.

## 3. معايير لوحات التحكم والرسوم البيانية الصادقة (Honest & Calm Dashboards)

خاص بأنظمة التداول ولوحات المراقبة مثل `Forex Trading System`:
1. **الأرقام أحادية المسافة والجدولية (Tabular Figures):**
   - استخدام `font-variant-numeric: tabular-nums` أو الخطوط الأحادية (`DM Mono`, `Geist Mono`, `Chivo Mono`) لجميع أرقام الأسعار، والربح/الخسارة (PnL)، ونسب المخاطرة، وزمن الاستجابة (Latency) لمنع اهتزاز الأرقام عند التحديث الحي.
2. **الرسوم البيانية الصادقة (Honest Visualizations):**
   - ممنوع التجسيم ثلاثي الأبعاد أو الانحناءات المضللة التي تحرف إدراك نقاط البيانات الحقيقية.
   - اعتماد خطوط أساس واضحة وصادقة (True Baselines / Zero Lines).
   - التدرجات اللونية الهادئة والمقاسة: استخدام ألوان الحالة المؤسسية (Graphite, Forest Green, Crisp Slate, Signal Red) بدلاً من الفسفوريات المشتتة.
3. **تطبيق قاعدة AGENTS.md الأولى:**
   - كل مؤشر أو عداد داخل لوحة التحكم يمثل إما بيانات حية من المحرك أو نتيجة اختبار حقيقي؛ يمنع منعاً باتاً كتابة أرقام إحصائية وهمية كـ "معدل فوز 99%" أو صفقات مختلقة.

## 4. الأدوات والسكربتات التنفيذية (CLI Suite)

تتواجد أدوات المهارة داخل `.agents/skills/taste-skill/scripts/` و`assets/`:

### أ) استخراج لوحات الألوان والخطوط المتوافقة
```bash
# توليد ثلاث لوحات ألوان وثلاث أطقم خطوط متناسقة مع طبيعة البرمجيات المالية
node .agents/skills/taste-skill/scripts/start.mjs deal --page software

# توليد متغيرات الـ CSS الصافية بناءً على الاختيار
node .agents/skills/taste-skill/scripts/start.mjs css --page software --palette <id> --type <id> --radius sharp
```

### ب) توزيع الهندسة البصرية لشاشة البطل (Hero Layout)
```bash
# تحديد التوزيع المثالي بين النص والواجهة البرمجية الحقيقية بدقة البكسل
node .agents/skills/taste-skill/assets/layout/deal.mjs --type software --has ui
```

### ج) الفحص الحتمي في متصفح Chrome الحقيقي (Consistency Checker)
```bash
# فحص الواجهة عبر 5 مقاسات عرض حقيقية وكشف أي خلل بصري أو تركيبي
node .agents/skills/taste-skill/scripts/consistency.mjs index.html --widths 1440,1024,820,768,390 --page software
```

### د) التقاط صور الشاشة للتحقق البصري الذاتي (Screenshots)
```bash
# تصوير الصفحة كاملة بدقة فائقة لمراجعتها
node .agents/skills/taste-skill/scripts/shoot.mjs --url index.html --w 1440 --out shots/desktop.png
node .agents/skills/taste-skill/scripts/shoot.mjs --url index.html --w 390 --out shots/mobile.png
```

### هـ) تدقيق الأداء وسرعة التحميل (Performance Audit)
```bash
# التأكد من عدم وجود انهيارات في الـ Layout Shift أو بطء في تحميل الخطوط والمجسمات
node .agents/skills/taste-skill/scripts/perf.mjs index.html
```

## 5. حلقة التصحيح الذاتي التلقائية (Autonomous Self-Correction Loop)

عند بناء أو تعديل أي واجهة مستخدم:
1. **Design & Build:** كتابة الهيكل والأنماط بناءً على التوزيع المختار من `deal.mjs` و`start.mjs`.
2. **Execute Consistency Audit:** تشغيل `consistency.mjs`.
3. **Capture Proof:** التقاط لقطات الشاشة عبر `shoot.mjs`.
4. **Autonomous Fix:** إذا أظهر الفحص أي علامة `FAIL` (مثل كسر في المحاذاة، أو تجاوز حاوية، أو عدم وضوح أزرار)، يقوم الوكيل بتحليل موقع الخطأ وتعديل الكود فوراً.
5. **Re-verify:** إعادة تشغيل الفحص حتى الحصول على حالة `PASS` نظيفة لجميع المقاسات.
